# FlowBench 현재 결과와 검증 범위

정리 기준: 2026-11-04 (Asia/Seoul). 이 문서는 현재 증거와 작동하는 기능의 검토용 요약입니다.

## 해결하려는 문제와 현재 질문

실제 절차에는 입구 대기줄이 없었습니다. 학생이 지정석에 앉은 뒤 반별로 확인·보고하는 절차에서 시간이 들었고, 사생회는 공동으로 착석 후 바로 공부를 시작하고 출석 확인은 별도로 진행하기로 결정했습니다. 준모는 직접 확인을 수행하고 과정과 시간을 보고했습니다.

현재 FlowBench의 질문은 **공부 시작을 무엇에 종속시켜야 하는지**, 그리고 **확인 담당자의 사전 정보·질문·재확인에 따라 업무가 어떻게 달라지는지**입니다. 소프트웨어는 익명 가상 조건을 비교하는 연구 도구입니다. 현장의 출석 여부를 자동 판정하는 시스템으로 운영되었다는 증거는 없습니다.

## 실제 절차를 모델로 옮긴 결과

학생은 세 경로를 [검토해 실제 방식과 맞다고 확인](../data/student-workflow-confirmation-2026-11-04.json)했습니다.

1. 직접 허가하여 이미 행선지를 알면 첫 질문을 건너뜁니다.
2. 모르면 동급생·친한 친구에게 묻고, 구체적인 행선지가 받아들여지면 추가 확인 없이 문의를 끝냅니다.
3. 잘 모르면 사감쌤이나 다른 리더에게 묻습니다.

v1의 ‘모든 가상 사례에 첫 질문 1회’ 가정은 첫 경로를 놓쳤습니다. v2는 사전 정보·친구 제보 종료·추가 문의 필요를 구별하고 합계가 보존되도록 고쳤습니다. [현재 모델 계약과 화면](INQUIRY_SCENARIOS_KO.md)에 입력·수식·가정·테스트가 연결되어 있습니다.

가상 10건에서 3건을 사전 정보 경로로 옮기면 첫 문의는 10회에서 7회가 되고, 사례당 가상 10초이면 첫 문의시간은 100초에서 70초가 됩니다. 사전 정보를 확보·유지·전달한 비용과 후속 질문시간은 미확인이므로 순 업무 절감이나 전체 확인시간 개선으로 부르지 않습니다.

## 담당자와 설명 가능한 범위

사용자는 본인이 직접 확인하지 않는 경우 부회장이나 여자 회장에게 맡기며, 그들의 확인 과정에는 크게 관여하지 않는다고 설명했습니다. [역할·관찰 범위 원문](../data/checking-delegation-scope-2026-11-04.json).

다른 담당자가 정보를 얻는 방법, 공유 명단의 유무, 질문 순서와 실제 시간은 미확인입니다. 준모가 직접 허가해 알고 있던 정보를 다른 담당자도 같은 비용으로 알고 있다고 가정하지 않습니다. 이 미확인 항목은 현재 검증의 범위 밖으로 남기고 추가 사실을 요구하지 않습니다. 이후 관련 관찰이 실제로 생기면 별도 출처로 추가할 수 있습니다.

## 작동하는 기능과 검증

- 순수 TypeScript FCFS·확인/보고 모델과 시간 의존관계 계산.
- 학생이 설명한 첫 문의 종료·불확실성 조건, 사전 정보로 질문 생략을 반영한 가상 비교.
- 조건별 건수·문의 횟수·알려진 시간과 미확인을 구분하는 화면·결과 막대.
- 원시 가상 입력·규칙 출처·가정·버전·미확인을 보존하는 JSON/CSV 직렬화와 내용 미리보기.
- 전체 **59개 테스트와 빌드 통과**, 데스크톱·휴대폰 화면 검증. 실제 브라우저 파일 다운로드 확인은 [#4](https://github.com/J0hns0n-K/FlowBench/issues/4)에 남아 있습니다.

수치 구현 검증과 실제 학교 절차의 예측 검증은 구별합니다. 뒷 단계의 종료 조건·충돌 답변·실제 오류율·다른 담당자의 업무량은 여전히 미확인입니다.

## 기여와 다음 개발 범위

준모의 보고된 기여는 잘못된 대기줄 전제의 수정, 현장 수행과 시간·맥락 보고, 선행 경험 문의, 문의 순서·종료 조건의 설명과 실제 절차 검토입니다. 절차 변경 결정은 사생회 공동 결정입니다. 초기 측정 친구와 선행 경험 졸업생의 기여도 별도로 기록합니다.

수학적 형식화·코드·기본 가상 예제·단위 테스트·화면·문서는 Codex 보조 구현입니다. 학생의 독립 코드 수정과 독립 검증 완료를 주장할 근거는 아직 없습니다. [기여 원장](CONTRIBUTIONS.md)에 역할을 구분했습니다.

현재 구현 단계는 재현 가능한 v2 비교 도구까지입니다. 다음 개발 후보는 미확인 상태가 끝까지 남는 경우와 상충하는 정보의 처리입니다. 그 규칙이 실제로 정해지거나 명시적인 가상 가정으로 채택될 때 구현합니다. 지금은 추가 시간 측정·정보 전달 조사·계산 연습을 요청하지 않습니다.
