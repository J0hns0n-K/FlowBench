# 학생 제출 절차 — 미확인 상태의 문의 순서

제출일: 2026-10-31 (Asia/Seoul). [사용자 원문 기록](../data/student-escalation-procedure-2026-10-31.json).

[단계별 관찰 후 설계 과제](STAGE_TIMING_02_KO.md)는 ‘지정석이 비었고 외출 정보도 없을 때, 어떤 확인을 거쳐 학생의 상태를 판단할지’였습니다. 사용자는 다음 순서를 제출했습니다.

| 단계 | 학생이 제시한 문의 대상 | 방법 |
| --- | --- | --- |
| 1 | 동급생이나 친한 아이 | 물어봄 |
| 2 | 리더나 12학년 | 물어봄 |
| 3 | 사감쌤 | 물어봄 |
| 4 | 교장쌤 | 전화함 |

이는 학생이 설명한 절차 순서입니다. 학교의 공식 규정으로 확인되었거나 네 단계를 실제로 모두 거친 사례가 보고된 것은 아닙니다. ‘리더’의 구체적 역할도 아직 정하지 않습니다. 문의 대상의 순서는 학생 제출 기여이고 아래 상태·조건 정리는 Codex 보조 설계입니다. 새로운 관찰 회차나 시간 측정 자료가 아닙니다.

## 소프트웨어로 옮길 부분과 아직 정하지 않은 부분

초기 상태는 **미확인**, 문의 대상은 위 순서로 기록할 수 있습니다. 후속 답변에서 사용자는 친구에게 **‘정확히 어디로 갔는지’** 듣고 **‘더 확인은 안해’**라고 설명했습니다. [종료 기준 원문](../data/student-peer-stopping-rule-2026-10-31.json)에 두 답변을 함께 보존했습니다.

따라서 첫 문의에서 구체적인 행선지를 들으면 **추가 확인 없이 문의를 종료한다**는 기준은 학생 제출 규칙입니다. 이어 사용자는 **‘잘 모르면 사감쌤이나 다른 리더들한테 물어봐’**라고 조건을 추가했습니다. [불확실할 때의 후속 문의 원문](../data/student-uncertain-followup-rule-2026-10-31.json)을 별도로 연결합니다. 사감쌤과 다른 리더 중 누가 우선인지는 제시되지 않았으므로 반드시 네 단계 전체를 순서대로 거친다고 모델링하지 않습니다.

문의 종료 상태는 **‘행선지 전달받음 — 친구 제보에 근거한 종료’**로 표현합니다. 이는 공식 확인·허가 확인·실제 위치 검증 완료를 뜻하지 않습니다. 구체적인 행선지를 듣는 조건을 생략하고 ‘누가 답하면 종료’로 일반화하지 않습니다. ‘잘 모름’을 누가 어떤 기준으로 판단하는지는 아직 미정입니다.

| 상황 | 보조 설계 초안 | 학생 기준·검토 상태 |
| --- | --- | --- |
| 구체적인 행선지를 듣고 잘 모르는 상태가 표시되지 않음 | 추가 문의를 종료하고 친구 제보임을 표시 | 학생 종료 기준과 후속 조건을 함께 반영한 보조 형식화 |
| 잘 모르는 상태 | 사감쌤 또는 다른 리더에게 후속 문의 | 학생이 명시한 조건·대상; 두 대상의 순서는 미정 |
| 행선지가 구체적이지 않지만 불확실성 표시는 없음 | 종료 기준 미충족으로 보고 후속 문의 | 조건 누락을 피하기 위한 보조 설계 |
| 두 번째 이후 문의에서 답변을 얻음 | 근거와 출처를 별도로 기록 | 각 단계의 종료 기준은 아직 구체적으로 제출되지 않음 |
| 현재 단계에서 해결하지 못함 | 다음 문의 대상으로 진행 | 원문의 순서를 바탕으로 한 조건 해석; 명시적 조건은 미제출 |
| 답변끼리 충돌하거나 상대에게 연락되지 않음 | 해결되었다고 자동 처리하지 않음 | 재시도·기다림·다음 단계 진행 기준 미정 |
| 마지막 문의 후에도 해결하지 못함 | 미해결 상태를 유지하고 별도 검토 필요 표시 | 최종 담당·완료 조건 미정 |

친구의 구체적 행선지 전달 후 종료와 잘 모르면 사감쌤·다른 리더에게 묻는 것은 학생 제출 규칙입니다. 나머지 예외 조건은 보조 초안입니다. 친구가 잘못 알고 있을 가능성, 허가 여부와 실제 위치는 이번 규칙으로 검증되지 않습니다. 학교 공식 기준으로 채택되었다는 근거도 없습니다. 자동 결석 판정이나 자동 연락 기능으로 확대하지 않습니다.

## 시간 모델에 주는 의미

최초 질문 이후에도 해결되지 않으면 문의 단계가 늘어날 수 있습니다. 따라서 질문 횟수뿐 아니라 **어느 단계까지 갔는지**, **그 단계에서 해결되었는지**가 모델의 입력 후보입니다. 조건부 종료 초안에서는 매번 네 단계 시간을 모두 더하는 고정 절차로 취급하지 않습니다. 단계별 소요시간, 상대를 찾거나 기다리는 시간과 해결 비율은 미확인입니다. 기존 11초·14초·13초·17초·23초를 특정 문의 대상에 배정하거나 가상 계수를 현장 값으로 만들지 않습니다.

기존 시간 의존관계 모델은 정해진 작업 경로의 종료시간을 계산합니다. 첫 문의의 조건부 판단은 아래 별도 모듈에 구현했습니다. 전체 후속 문의 경로·최종 완료시간이나 답변의 실제 신뢰성을 계산하는 기능은 아직 아닙니다.

## 구현과 검증 — 첫 문의만

[판단 모듈](../src/inquiry-policy.ts)의 `evaluatePeerEnquiry`는 익명 가상 입력만 받습니다. 구체적 행선지 여부와 불확실성 여부를 모두 명시해야 하며, 빠진 불확실성 입력을 ‘확실함’으로 바꾸지 않습니다. 이는 사용자의 언어 조건을 보조자가 두 개의 명시적 입력으로 옮긴 것이며 문장에서 확신을 자동 판별하지 않습니다.

- 불확실성이 표시되면 구체적인 장소를 언급했더라도 후속 문의를 선택합니다.
- 후속 대상은 리더·사감쌤의 선택지이며 실제 연락이나 고정된 순서가 아닙니다.
- 출력은 `closed-on-peer-report` 또는 `follow-up-required`이고, 두 경우 모두 독립 검증 여부는 `not-established`입니다.
- 문의시간 `null`은 그대로 유지합니다. 기존 현장 질문시간을 자동 배정하거나 후속 문의의 전체 시간을 추정하지 않습니다.

아래 가상 사례를 포함해 [새 테스트 5개](../tests/inquiry-policy.test.ts)를 구현·실행했습니다. 코드와 테스트는 Codex 보조 작업이며 실제 관찰·학생 작성 테스트·정책 승인으로 간주하지 않습니다. 전체 테스트는 50개 통과, 형식 검사·브라우저 빌드도 통과했습니다. 이 모듈은 아직 브라우저 화면에 연결하지 않았습니다.

| 가상 입력 | 예상 동작·검토 상태 |
| --- | --- |
| 친구가 구체적인 장소를 알려주고 불확실성 표시 없음 | 문의 종료. 친구 제보라는 출처와 독립 검증 미확립을 유지 |
| 구체적인 장소를 말하지만 잘 모르겠다고 표시됨 | 후속 문의. 장소의 구체성만으로 종료하지 않음 |
| 친구가 ‘어딘가 나간 것 같다’고만 답함 | 구체적 행선지 기준을 충족하지 않음. 후속 문의는 보조 설계 |
| 친구가 구체적인 장소를 말했으나 실제로는 틀림 | 현재 규칙은 여전히 문의를 종료할 수 있음. 절차 종료와 사실 정확성이 다를 수 있다는 반례 |

추가 테스트는 입력 누락·잘못된 측정값·실제 현장 출처의 혼입을 거절하고, 알 수 없는 시간과 명시적 0을 구별합니다. 잘못된 제보도 확신 있게 전달되면 현재 규칙으로 종료할 수 있다는 반례를 보존합니다. 불확실할 때 다시 묻는 규칙이 이 경우까지 자동으로 검출하지는 못합니다.

다음 개발 단계는 이 분기 결과를 익명 가상 시나리오의 문의 횟수·시간 비교에 연결하는 것입니다. 뒷 단계의 종료 기준이나 실제 정확도를 임의로 채우지 않습니다. 새로운 현장 측정 요청은 보류합니다.
