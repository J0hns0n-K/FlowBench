## 먼저 기록할 사건

하나의 연속 타이머에서 다음 사건을 기록합니다. 원래 운영 절차를 바꾸거나 출석 확인을 위해 사람을 새로 호명하지 않습니다.

- C: 카운트다운 시작.
- E: 카운트다운 종료.
- D: 실제 정해진 25분 마감 시점. 시간대와 실제 시각은 관찰할 때 기록.
- I: 입실 시작, S: 모두 착석. 최신 약 60초가 지칭하는 구간은 S-I이며, 마감 이후 준비 P와 같다고 단정하지 않기.
- A: 첫 반의 인원 확인을 시작하는 관찰 가능한 행동/요청. 판정 기준을 관찰 전에 적기.
- F: 마지막 반의 보고 완료.

주관적인 “진정됐다”는 느낌을 정확한 센서 수치인 것처럼 다루지 않습니다. A는 일관된 관찰 사건으로 정하고, 학생이 말한 착석·진정 과정 외의 진행 대기까지 포함할 수 있다는 한계를 기록합니다.

관찰된 순서가 `D <= A <= F`일 때:

```
준비·진행 대기 P = A - D
확인·보고 V = F - A
마감 이후 총 완료시간 T = F - D = P + V
```

순서가 다르면 그대로 기록하고 위 분해가 그 세션에 맞는지 검토합니다. 카운트다운은 마감 전에 발생하므로 길이 `E-C`를 P+V에 무조건 추가하지 않습니다. 착석·진정 자체의 길이와 마감 이후 대기 P는 정의가 다를 수 있습니다.

## 기존 시뮬레이터와의 관계

기존 엔진의 t=0은 모델링한 첫 인원 확인 시작 A에 대응하며, 결과는 **V에 관한 합성 실험**입니다. 268초와 78초는 잠긴 합성 예제의 결과로 유지합니다. 최신 사용자 보고 V≈120초에 보정된 값이 아닙니다. 총 확인시간 120초만으로 8개 반의 확인·보고 시간을 각각 알아낼 수 없으므로 임의 균등 배분하지 않습니다. 현재 앱으로 P 또는 전체 T가 줄었다고 주장할 수 없습니다.

같은 준비시간 P가 유지되고 확인 방법만 바뀐다는 조건에서:

```
T_기준 = P + V_기준
T_대안 = P + V_대안
전체 절감 비율 = (V_기준 - V_대안) / (P + V_기준)
```

따라서 확인 단계의 절감 비율을 전체 과정의 절감 비율로 옮겨 쓰면 안 됩니다. 예를 들어 **가상으로** P=90초, V_기준=90초, V_대안=45초라면 확인 단계는 50% 짧아도 전체는 180→135초로 25% 짧습니다. 이 숫자는 설명용 산술 예시이며 학교 예측이나 결과가 아닙니다.
