# 같은 표현에서 실제 같은 장소를 알아낼 수 있는가

2026-11-18 (Asia/Seoul). [작업 #13](https://github.com/J0hns0n-K/FlowBench/issues/13).

## 연구 질문과 검토할 주장

두 제보의 글자와 정해 둔 번역 별칭만으로, 두 제보가 같은 물리적 장소를 가리키는지 알아낼 수 있는가?

보조자가 검토용으로 설정한 주장 H-L은 **“별칭 정리 후 두 표현이 같으면 두 제보가 가리키는 물리적 장소도 같다”**입니다. 이를 반증하는 데에는 표현이 같으면서 장소는 다른, 허용 가능한 가상 상황 한 개가 충분합니다. 학생이 이 주장을 제안하거나 채택했다고 기록하지 않습니다.

사용자는 번역 표현 사례로 ‘병원, hospital’을 선택했습니다. 아래 가능 상황과 증명·실행기는 Codex가 기존 구현을 만든 뒤 구성했습니다. 사전등록·독립 검증 표본·학교에서 관찰한 사례로 분류하지 않습니다.

## 구분할 수 없는 가상 상황

모든 A/B 장소 식별자는 합성 식별자입니다. 실제 병원·학생·허가 내역을 나타내지 않습니다.

| 가상 상황 | 코드가 받는 두 답변 | 가상 설정 속 장소 | 원문 결과 | 별칭 후 결과 |
| --- | --- | --- | --- | --- |
| 번역 표현·같은 장소 | 병원 / hospital | A / A | conflict | same |
| 번역 표현·다른 장소 | 병원 / hospital | A / B | conflict | same |
| 같은 표현·같은 장소 | 병원 / 병원 | A / A | same | same |
| 같은 표현·다른 장소 | 병원 / 병원 | A / B | same | same |

장소 A/B는 평가에서 비교할 정답을 구성하는 숨은 설정입니다. 표현 비교 함수에는 **두 답변 문자열만** 전달합니다. 각 쌍에서 입력과 실행 메타데이터가 같으므로 완전한 비교 기록도 같습니다. 실제 장소 관계를 다르게 설정해도 함수가 관측할 수 있는 값은 바뀌지 않습니다.

번역 표현의 경우 별칭 정리로 conflict가 same으로 바뀌지만, A/A와 A/B를 구별하는 정보는 생기지 않습니다. 같은 표현 쌍에서도 두 결과 모두 same이므로 이 한계는 별칭 추가 이전에도 존재합니다.

## 수학적 설명

함수의 입력을 두 문자열의 쌍 `x`, 두 실제 장소의 일치 여부를 `y ∈ {0, 1}`이라 두겠습니다. 구성한 두 상황 `w₁`, `w₂`는 다음 조건을 만족합니다.

```text
x(w₁) = x(w₂)
y(w₁) = 1, y(w₂) = 0
```

같은 입력만 받는 결정적 함수는 두 상황에서 같은 `f(x)`를 반환합니다. 그 하나의 값을 두 상황의 서로 다른 `y`와 동시에 같게 만들 수 없습니다. 따라서 이 가능 상황들을 모두 허용하는 범위에서 `x`만으로 `y`를 식별할 수 없습니다. same/conflict/unknown은 표현 비교의 상태로 유지하며 물리적 장소 일치 여부는 검증 미확립으로 남깁니다.

H-L의 전제가 참이고 결론이 거짓인 A/B 상황이 있으므로 H-L은 이 반례에 의해 기각됩니다. 이는 일반적인 표현 정리의 유용성이나 검증된 고유 장소 코드의 가능성을 부정하는 주장은 아닙니다. 현재 자유 입력과 명시 별칭이 담고 있는 정보의 범위를 한정합니다.

## 실행과 검증 지표

- [고정 가상 입력 4개](../data/label-comparison-twin-worlds-v1.json): 서로 구별되지 않는 입력 쌍 2개. 각 쌍에 A/A와 A/B를 포함합니다.
- [실행기](../scripts/label-comparison-limits.mjs): 원문·별칭 결과, 같은 입력의 완전한 기록 일치, 서로 다른 가상 장소 정답, 합성 출처와 검증 미확립 표시를 확인합니다. 하나라도 깨지면 실패합니다.
- [실행 결과](../experiments/2026-11-18-label-limits-v1.json): 원래 입력·가상 장소·두 결과·두 반례 증서·소스 파일 목록·Git revision·SHA-256 fingerprint·생성 시각을 보존합니다. fingerprint는 명시한 네 소스 파일의 경로와 LF로 정리한 내용을 대상으로 합니다.
- 검증 결과는 **4개 가상 상황, 2개 식별 불가능 입력 쌍**입니다. 표본이 반례를 보이도록 구성됐으므로 이 비율로 현장 오분류율을 추정하지 않습니다. empiricalAccuracy는 null입니다.
- 검증 과정에서 저장 증서의 장소 식별 결과를 의도적으로 true로 바꾸자 실행기가 불일치를 거부했습니다. 원본을 복원한 뒤 재실행은 통과했습니다. 저장 기록의 생성 시각·revision도 비교 기록의 루트 메타데이터와 일치하는지 검사합니다.

```text
pnpm label:limits
node scripts/label-comparison-limits.mjs --write
```

첫 명령은 고정 자료를 다시 실행해 저장된 결과와 대조하고 검증 요약을 출력합니다. 생성 시각·실행 당시 revision만 제외하고 소스 fingerprint와 모든 입력·판정·반례 증서가 일치해야 통과합니다. 두 번째 명령은 현재 소스 revision·생성 시각으로 JSON 결과를 갱신합니다. timestamp와 revision이 달라도 반례의 입력·결과·식별 불가능성은 재현되어야 합니다. 초기 저장 결과는 구현 중 revision에 dirty suffix를 붙였고, 같은 코드 내용을 fingerprint로 식별합니다. CI도 같은 실행기를 실행합니다.

## 프로젝트에 미치는 영향

현재 화면·내보내기 계약·문의 규칙은 유지합니다. 별칭 후 same을 출석 확정이나 같은 특정 병원에 있다는 증거로 승격하지 않습니다. 나중에 실제 장소를 식별하는 기능을 연구한다면 표현 외에 장소를 구별하는 근거와 그 근거의 신뢰도를 별도 변수로 설계해야 합니다. 이번 결과는 그런 근거를 새로 수집하거나 검증한 결과가 아닙니다.

학생 기여는 앞선 가상 번역 표현 선택입니다. 반례 구성·주장 정식화·수학적 설명·실행기·CI 연결은 Codex 보조 작업입니다. 이 기록은 새로운 현장 관찰·독립 정확도 검증·학생의 독립 연구 발견을 추가하지 않습니다.
