# 같은 출첵 2분으로도 개선 예측이 달라지는 이유

2026-10-27. 사용자에게서 받은 자료는 채플실 시계를 참고한 **약 2분의 확인시간**과 8개 반이라는 구조입니다. 아직 반별 확인·보고 시간은 없습니다. 이 집계값만으로 동시 확인의 효과를 확정할 수 있는지 기존 엔진으로 점검했습니다.

## 두 개의 가상 설명

아래는 **합성 반례**입니다. 각 반에 같은 시간이 걸린다는 설정도 예시일 뿐 실제 반별 시간을 균등 배분한 관측값이 아닙니다. 약 120초라는 보고값을 설명하는 여러 모델이 가능함을 보입니다.

| 가상 설정: 8개 반 | 반별 확인 | 반별 보고 | 순차 확인 총시간 | 동시 확인+보고 담당 1명 |
| --- | ---: | ---: | ---: | ---: |
| 확인 작업이 대부분 | 14초 | 1초 | 120초 | 22초 |
| 보고 작업이 대부분 | 1초 | 14초 | 120초 | 113초 |

손계산: 두 설정 모두 순차 총시간은 `8 × (14+1) = 120초`입니다. 모두 동시에 확인하고 같은 시각에 보고 준비를 마친다는 가정에서는 `확인시간 + 8 × 보고시간`이므로 각각 `14+8=22초`, `1+112=113초`가 됩니다.

기존 `compareWorkflows` 실행에서도 이 값이 나왔습니다. 이론상 확인 단계 절감 비율은 각각 약 81.7%와 5.8%로 다르지만, **어느 값도 학교 예측 또는 측정된 개선 효과가 아닙니다**. 준비·착석 시간은 이 비교에 포함하지 않았습니다.

## 재현

Node.js 24 이상에서 기존 엔진의 `compareWorkflows`에 아래 두 그룹 배열을 넣고 목표를 120으로 두면 됩니다.

```ts
import { compareWorkflows } from '../src/workflow.ts';

for (const [countSec, reportSec] of [[14, 1], [1, 14]]) {
  const groups = Array.from({ length: 8 }, (_, i) => ({
    id: `G${i + 1}`, countSec, reportSec,
  }));
  const result = compareWorkflows(groups, 120);
  console.log(result.baseline.metrics.totalSec,
              result.candidate.metrics.totalSec);
}
// 120 22
// 120 113
```

위 코드를 docs/ 아래의 임시 TypeScript 파일로 실행하면 상대 경로가 맞습니다. 프로그램의 기본 합성 예제나 사용자 보고 데이터는 바꾸지 않습니다.

## 연구상 결론

지금 자료는 “출첵 단계가 약 2분”이라는 현장 맥락을 뒷받침하지만, 그 2분의 구성이나 변경 효과를 식별하지 못합니다. 단순히 총시간에 맞춘 모델이 현재 절차를 정확히 설명한다고 볼 수 없습니다. 다음 관찰은 반별 진행 구간과 가능하면 확인/보고의 구분을 기록하는 데 초점을 둡니다. 구분이 관찰되지 않으면 임의로 만들어 채우지 않습니다.

준모가 직접 할 분석: 위 두 경우를 손으로 계산하고, 어떤 추가 관찰이 두 설명을 구별할 수 있는지 적습니다. 이 반례와 문서는 AI가 작성했으므로 학생의 독립적인 모델 설계로 주장하지 않습니다.
